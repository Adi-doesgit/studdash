2. 🔄 CI/CD Pipeline Workflow

Why CI/CD?

  • Eliminates "works on my machine" problems
  • Automates testing, building, scanning, and publishing
  • Catches security vulnerabilities before deployment
  • Every merge to main produces verified container images

6. 🎤 Presentation Speaker Script

🎙️ Speaker 1 — Product & Frontend Lead
"We built StudDash — a minimal, containerized student dashboard. It solves a real problem: universities lack a centralized system for marks, notes, and assignments."

Roles: Admin (manage users + metrics) · Teacher (upload notes, view submissions) · Student (view marks + GPA, upload assignments)

"The frontend uses Vite + React with role-based rendering — a student never sees admin routes. Our ProtectedRoute component enforces this."

Demo: Login → Student dashboard (marks + GPA) → Notes → Admin panel (users + Grafana metrics)

⚙️ Speaker 2 — Backend API Architect
"Our backend has 5 route modules under /api — auth, grades, notes, assignments, and admin. Every protected request passes through a three-layer middleware chain: authenticate (JWT) → requireRole (RBAC) → handler."

File uploads: Multer — PDF only, 20MB max, timestamp-based naming

"We handle SIGINT and SIGTERM for graceful shutdown. When Kubernetes terminates a pod, we close HTTP connections, drain the PostgreSQL pool, and exit cleanly."
🔐 Speaker 3 — Security & Database Admin
"PostgreSQL 16 with 6 normalized tables — users, subjects, registrations, grades, notes, assignments. Foreign keys with CASCADE, unique constraints, CHECK constraints for role validation."
"Security at every layer: bcrypt for passwords, JWT for stateless auth, RBAC middleware for access control, non-root containers, and Trivy scanning for CVEs."
🐳 Speaker 4 — DevOps Engineer
"Multi-stage Docker builds keep images small and secure. docker-compose up --build brings up all 5 services."
"Our CI pipeline: install → test → build → Trivy scan → push to Docker Hub. This eliminates 'works on my machine' — every merge produces verified, scanned images."
☸️ Speaker 5 — Cloud & Kubernetes Lead
"We deploy to a Kind cluster on WSL2. 3 Deployments, 3 ClusterIP Services, NGINX Ingress for routing, 2 PVCs for persistent storage, Kubernetes Secrets, and HPA for auto-scaling."
"Backend pods have liveness and readiness probes. Prometheus scrapes metrics every 15s. Grafana displays request rates, latency, and CPU usage."

"This system is designed to be minimal yet scalable, combining clean architecture, containerization, and real-time monitoring to deliver a production-like environment."
